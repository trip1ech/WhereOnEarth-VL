# 中央標線裁切與 ViT 診斷

## 問題與做法

比較整圖和中央線放大後的特徵表現，判斷這個線索的辨識問題是否足以支持微調 ViT。

- 沿用原始 23 張單線、20 張雙線和既有的切分。第一輪按拍攝者分 5 折。第二輪使用 8 國的 11 組同國單／雙線照片，每輪把整個國家留作測試。
- 我用不顯示標籤及預測的照片縮圖，逐張選一個中央線附近的中心點。裁切視窗固定為原始寬、高各 48%，範圍超出時平移至畫面內。裁切後放回原像素尺寸，因此模型的影像 token 數維持一致，約放大線性尺寸 2.1 倍。固定裁切組也用相同尺寸，中心一律在寬 50%、高 76% 的位置。
- 濕暗、陰影、複雜路口與分隔線難以判定的 10 張另做記號，保留原有標籤及主要分析。抽查裁切後的照片可看到，固定裁切可能裁到人行道或錯過離畫面中心較遠的標線。有些照片即使選好區域，仍難從局部判斷哪條線分隔對向車流。
- ViT、projector 與 LM 的權重在擷取過程保持凍結。線性分類器使用與整圖試驗相同的彙整、超參數與切分。直接問答則照原本方式交換 A/B 選項並平均兩次的分數。
- 這是中央線辨識診斷。這些圖曾出現在 6,000 張的定位 LoRA 訓練資料中。要決定是否把視覺微調用於 GeoGuessr，仍須在未見拍攝者的資料上量測國家準確率與定位誤差。

可在 review 資料夾的 compare-1.jpg 和 compare-2.jpg 檢視三種輸入範例。crop_centers.csv 保存中心點和目視不確定標記。

## 結果

平衡準確率等權平均單線與雙線的答對率。22 張子集恰好各 11 張，所以也等於答對張數所占比例。

| 方法 | 43 張整圖 | 43 張固定裁切 | 43 張人工裁切 | 22 張整圖 | 22 張固定裁切 | 22 張人工裁切 |
|---|---:|---:|---:|---:|---:|---:|
| ViT 最後一層、分區平均 | 49.2% | 34.6% | 41.7% | 54.5% | 50.0% | 50.0% |
| ViT 最後一層、保留 patch 相對位置 | 57.9% | 34.6% | 53.3% | 59.1% | 50.0% | 54.5% |
| 主 projector | 43.6% | 41.4% | 65.1% | 50.0% | 54.5% | 72.7% |
| Projector 加 DeepStack | 41.4% | 47.9% | 58.3% | 54.5% | 63.6% | 81.8% |
| 縮小的全圖 RGB | 51.1% | 51.1% | 41.4% | 50.0% | 45.5% | 45.5% |
| 原版 Qwen 問答 | 54.0% | 58.4% | 71.7% | 63.6% | 72.7% | 81.8% |
| 6,000 張定位 LoRA 問答 | 62.7% | 60.2% | 78.3% | 72.7% | 68.2% | 86.4% |

- 在 22 張子集，人工裁切讓 projector 加 DeepStack 由 12/22 到 18/22，其中 7 張由錯變對、1 張由對變錯。原版 Qwen 多答對 4 張且無退步，定位 LoRA 多答對 3 張且無退步。人工裁切都優於同尺度的固定裁切。
- 在 11 組同國配對裡，人工裁切後 projector 加 DeepStack、原版 Qwen、定位 LoRA 分數皆能把 11 組排對。縮小 RGB 排對 6 組。兩版 Qwen 的平均雙線分數在這批 43 張人工裁切圖上的 AUROC 都是 1.00，代表這批每一張雙線的分數皆高於每一張單線。二選一用零作判斷門檻，原版仍只答對 10/23 張單線，LoRA 答對 13/23，雙線都答對 20/20。原版與 LoRA 各只有 28/43 與 21/43 張在交換 A/B 後仍選同一類。
- 最後一層 ViT 的分區平均和保留 patch 位置版本在人工裁切後均未提升。主 projector 和結合 DeepStack 的特徵都有增益，因此低的末層 probe 分數只能說明指定的線性讀取方式表現弱。DeepStack 經不同層的投影後再做拼接，這個設計無法把優勢拆成投影本身或中間層特徵的貢獻。
- 22 張配對只有 1 張被標為目視不確定。扣除這張看已留出預測，projector 加 DeepStack 是 12/21 到 17/21，原版 Qwen 是 14/21 到 18/21。主要方向也出現在 43 張作者切分，但效應幅度依讀取方式而變。

## ViT 決策

現階段維持 ViT 凍結。原版 Qwen 使用相同的權重，給它位置較準的局部視野就更能區分標線。在這批資料上，先增加關鍵區域的可見度比解凍 ViT 有更直接的依據。人工選區用了位置先驗，裁切仍可保留路面或攝影捷徑。下一個能影響 ViT 決策的測試，是在未見拍攝者上，以能自動取得的道路裁切搭配整圖做地理定位，量測實際的定位誤差。若清楚的局部圖上仍有可重現的視覺辨識錯誤，且錯誤影響定位，再試小範圍的 Vision LoRA。

### 待驗證的 LM 假說

整圖的影像特徵可能已包含中央線資訊，但 LM 答題時未充分利用。裁切是在 ViT 之前做的，會同時放大標線與去除周邊內容，影像 token 數維持一致。22 張子集上，原版 Qwen 從 14/22 提升到 18/22，而跳過 LM、用 projector 加 DeepStack 分類也從 12/22 提升到 18/22。因此，特徵本身變得更容易讀取，也可能解釋部分增益。

後續測試先對完整原圖抽取一次視覺特徵，固定 ViT 與各路 projector／DeepStack 輸出。用相同問句與選項順序對照，只改 LM 可讀取的影像位置，比較全部位置、中央線附近、以及同樣數量的鄰近無標線路面位置。若只聚焦中央線就能提升辨識，會更支持整圖中已有可用訊號、差別在於 LM 如何使用它。

## 重現

`comparison.json` 保存各組分數和逐圖改善／退步數。兩個裁切組各有 `out_of_fold.csv`、`analysis.json`、`roadmark-features.zip`。從專案目錄重算：

```sh
for view in marked fixed; do
  python -B scripts/analyze_roadmark_probe.py \
    --results "results/roadmark_crop_probe/$view" \
    --labels results/roadmark_probe/labels.jsonl \
    --inference-input results/roadmark_crop_probe/inference-input.zip
done
python -B scripts/compare_roadmark_crop_probe.py
```

如要重新抽取，先執行 `python -B scripts/prepare_roadmark_crop_probe.py`，用 `split -b 4m -a 2 results/roadmark_crop_probe/inference-input.zip results/roadmark_crop_probe/transfer/part-` 切分，再執行 `bash results/roadmark_crop_probe/transfer/run.sh`。
